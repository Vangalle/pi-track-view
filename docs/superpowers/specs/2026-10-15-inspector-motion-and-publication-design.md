# Inspector presentation and public source publication

## Outcome

The session viewer retains a usable tree while comparing JSON: ordinary and pinned record drawers have the same default height. The whole-session VS Code action belongs beside the session/file controls, not inside an individual-record drawer. A record drawer can be temporarily brought to the screen center against a dim backdrop without changing its height, its JSON, or the pin. Motion is smooth, restrained, responsive, and disabled when the OS requests reduced motion. After verified implementation, the source is published to a new **public** `Vangalle/pi-track-view` GitHub repository on `main`; this does not deploy the server as a website.

## Existing flow and changes

- Keep one shared `/` and `/preview` document and renderer. The inspector is still one bottom-fixed element displaying the selected entry or, when pinned, left and right JSON with separate internal scroll areas. Remove pinned-only height overrides (including mobile overrides); the bottom and centered versions use the same `min(44vh,360px)` base height. Narrow screens stack JSON columns inside that height and scroll each column.
- Move the existing `previewEditor` button (and its authenticated `/api/sessions/{id}/open-editor` behavior) from the inspector to the main workbench file/session action row. Disabled for demo/no real session, enabled for a real session independent of drawer visibility and of pin/focus. No new endpoint and no mutation of the uploaded source.
- Add a `Focus view` button in the inspector header. Clicking it moves the *same* inspector from bottom to centered within the viewport, retains the current record(s), shows a single semitransparent backdrop, and updates button label/pressed state to `Return to bottom`. Clicking it again, clicking the backdrop, or pressing Escape returns the inspector to bottom without closing it or unpinning. The close × button closes the inspector and clears the centered presentation (not the pin). Session switches, filter changes, or gap collapse that already close the inspector also clear centered presentation and backdrop. The inspector remains above both ordinary and fullscreen/immersive tree views.
- Centering uses CSS transition of `bottom` and `transform` (same fixed element, no DOM reparent), and backdrop uses `opacity`/`visibility`; no movement of the tree or mutation of annotations. In centered mode the inspector has dialog semantics and keyboard focus stays within it until returned/closed; restoration returns focus to the invoking control when appropriate. `prefers-reduced-motion: reduce` removes nonessential transitions and animations. Focus/hover controls, tree cards, and type-filter popup receive restrained 150–300 ms transitions. Avoid per-node layout animation: sessions can have thousands of entries.
